# 2026-05-15 SQL/DB 배포 안정화 기록

## 배경

초기 SQL은 테이블명이 대문자(`ACCOUNT`, `ITEM`, `ORDERS` 등)였고, 일부 Repository/mapper SQL은 소문자 테이블명을 참조할 수 있는 상태였다.

Windows MySQL에서는 대소문자 문제가 드러나지 않을 수 있지만, Linux 배포 환경에서는 `lower_case_table_names` 설정과 파일시스템 특성 때문에 테이블명 대소문자 불일치가 `Table ... doesn't exist` 오류로 이어질 수 있다.

## 처리 내용

- `src/main/resources/SQL/schema.sql`
  - 테이블명, 컬럼명, 인덱스명, 제약조건명을 lower snake case 기준으로 정리했다.
  - 예: `ACCOUNT` -> `account`, `ACCOUNT_PK` -> `account_pk`.

- `src/main/resources/SQL/sample.sql`
  - schema 기준에 맞춰 insert 대상 테이블/컬럼명을 lower snake case로 정리했다.
  - 관리자 샘플 계정은 `account_id = admin`, 비밀번호 기준값은 `Admin1234!@`로 문서화했다.

- `src/main/java/bugsandwich/ornably/**/*Repository.java`
  - SQL 문자열 안의 테이블/컬럼 참조를 lower snake case로 맞췄다.
  - Java 상수명과 condition 문자열은 런타임 분기 키이므로 유지했다.

- `src/main/resources/mapper/*.xml`
  - MyBatis mapper SQL의 테이블/컬럼 참조를 lower snake case로 맞췄다.
  - 실수로 들어간 literal `` `t`` 문자를 제거했다.
  - `ConnectLogMapper.xml`의 id와 `ConnectLogRepository` 호출명을 `selectAll`, `selectOne` 기준으로 맞췄다.

- Docker/MySQL 설정
  - DB schema는 `ornably_db`, 일반 사용자는 `kevin` 기준으로 맞췄다.
  - `application-docker.properties`의 datasource URL은 `jdbc:mysql://mysql:3306/ornably_db?${DB_OPTIONS}` 기준으로 정리했다.
  - dev compose는 MySQL/Redis 포트가 고정 공개되는 구조로 문서화했다.
  - auto compose는 `.env.docker`를 기본으로 사용하고, override가 `.env`와 함께 포트를 공개하는 흐름으로 정리했다.

## 인코딩/문자 깨짐 처리

PowerShell 기본 인코딩/저장 방식 영향으로 일부 Java/XML 파일의 한글 주석과 로그 문자열이 깨진 적이 있었다.

처리 방식:

- Git HEAD의 정상 UTF-8 원문을 기준으로 깨진 파일을 복원했다.
- 이후 SQL 식별자 변경만 다시 적용했다.
- 파일 저장은 UTF-8 no BOM 기준으로 맞췄다.
- `EventRepository.java`, Repository 파일들, mapper XML을 확인했다.

## 검증

실행한 검증:

```powershell
.\mvnw.cmd -q compile
.\mvnw.cmd -q -DskipTests compile
git diff --check
rg -n "``t" src/main/resources/mapper target/classes/mapper
```

결과:

- compile 통과
- mapper XML의 literal `` `t`` 제거 확인
- `git diff --check` 통과

주의:

- `.\mvnw.cmd clean compile`은 `target/test-classes` 삭제 실패로 중단된 적이 있다.
- 원인은 코드 문제가 아니라 IDE/실행 중인 프로세스가 `target` 폴더를 잡고 있을 가능성이 높다.
- 이 경우 앱/IDE 실행을 멈춘 뒤 다시 `clean compile`을 수행하면 된다.

## 남은 주의사항

- `target/classes`는 빌드 산출물이므로 원본은 항상 `src/main/resources`와 `src/main/java` 기준으로 확인한다.
- Docker DB 데이터를 초기화해야 schema 변경이 반영된다. 기존 MySQL volume/data가 남아 있으면 예전 대문자 테이블이 계속 남을 수 있다.
- Linux 배포 전에는 새 DB로 초기화한 뒤 `schema.sql`, `sample.sql`, Repository, mapper가 같은 테이블/컬럼명을 바라보는지 확인한다.
